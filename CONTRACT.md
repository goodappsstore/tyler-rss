# Tyler — build contract (single source of truth)

Tyler is a local-first RSS reader desktop app: Tauri 2 + React 19 + Vite, Rust backend, SQLite (FTS5).
Data dir: `~/.tyler-rss` (override `TYLER_DATA_DIR`), files: `tyler.sqlite`, optional `tts/<revision>/` (cached model/voices, excluded from backups), `media/` (feed icons, article cover images, inline images). Everything binary lives next to the DB.

**Product name:** Tyler. Never use the words calm, peaceful, quiet, serene, sanctuary, oasis, haven, breathe, mindful, distraction-free, cozy, curated with love, etc. Write plain, sharp product copy.

## Tauri commands (invoke args are camelCase from JS; Rust uses snake_case with `#[tauri::command(rename_all = "camelCase")]`)
- `bootstrap() -> Bootstrap`
- `fetch_article_source(articleId:number) -> {html:string,url:string}` — fetch the article's original HTTP(S) HTML in a blocking worker, 20s timeout, 5 MiB cap. Request URLs append `ref=tyler-rss.com` only when no `ref` query parameter exists, as do feed discovery/refresh and OPML link imports. Frontend uses Mozilla Readability in an inert document.
- `save_full_article(articleId:number,html:string,sourceUrl:string,expectedUrl:string) -> ArticleDetail` — sanitize extracted HTML, resolve relative URLs against final source URL, store text/reading time, set full-content flag, update FTS. Require the current article URL to match expectedUrl; refresh preserves extracted content.
- `open_article_link(url:string) -> void` — HTTP(S)/mailto only. Settings choose separate remote Tyler windows (no main capabilities) or system handler.
- `export_article_markdown(path:string,markdown:string) -> void` — write a user-selected `.md` file in a blocking worker. Frontend converts current sanitized HTML and metadata with Turndown.
- `print_article() -> void` — main webview native print on macOS; frontend uses `window.print()` on other platforms. Print CSS includes only the article; system PDF output where supported.
- `take_open_requests() -> string[]` — drain pending OPML paths/feed links. `desktop:open` signals new requests. Native file drop events import OPML; feed links open Add feed for review.
- `update_unread_badge(unread:number,enabled:boolean) -> void` — update Dock/supported taskbar badge, tray tooltip, and window title; numeric badge unsupported on Windows.
- `generate_summary(articleId:number) -> { text:string, cached:boolean, truncated:boolean }` — requires enabled, configured LLM settings. Reads source text/settings in a blocking worker, releases SQLite, and calls `<baseUrl>/chat/completions` with bearer authentication and system/user messages using the saved prompt. Input clipping covers title plus body (falling back to the feed summary). Positive output words set `max_tokens = ceil(words * 4/3)` and add an output word-count instruction; zero omits the token limit. Memory cache keys hash article ID/title/text, endpoint, key, model, prompt, and limits. Per-request locks coalesce concurrent generation; a matching completed response is returned from memory. Errors and empty responses are not cached. `truncated` reflects `finish_reason: "length"`. HTTP(S), 15s connect/180s total timeout, no redirects. No summary database writes.
- `list_articles(query: { filter:string, feedId?:number|null, folderId?:number|null, tagId?:number|null, search?:string|null, sort?:string, limit?:number, offset?:number, cursor?:ArticleCursor|null, includeArchived?:boolean }) -> { articles: ArticleSummary[], total:number, nextCursor:ArticleCursor|null }`
  - filter: "all" | "unread" | "starred" | "today" | "archived"; default "all".
  - search: FTS5 over title/content/author/feed title (prefix matching; support quoted phrases), fallback LIKE.
  - sort: "newest" | "oldest" | "feed".
  - Pass `nextCursor` unchanged as `cursor` to load the next page; null means the end. Cursor pagination is independent of read/star state changes to loaded articles. Reset it when the query changes. Offset is retained for older callers and ignored when a cursor is supplied.
  - Background refresh reads pages through the last loaded article, or to the end if that article no longer matches. Merge those rows while retaining the selection and use the last fetched page's cursor. Load-more deduplicates by article ID.
  - ArticleCursor: `{id, publishedAt, feedTitle, rank:string|null}`. Search rank uses a string for exact numeric round trips; callers should treat the whole cursor as opaque.
- `get_article(id:number) -> ArticleDetail` (marks nothing; frontend handles read state). prev/next by published_at desc within all non-archived articles.
- `set_article_state(id:number, patch:{isRead?:boolean,isStarred?:boolean,isArchived?:boolean}) -> Counts`
- `mark_all_read(scope:{feedId?:number|null,folderId?:number|null,tagId?:number|null,search?:string|null}) -> Counts`
- `discover_feeds(url:string) -> { candidates: {title,url,site_url,description,kind}[] }` — accepts site URL or feed URL; parse HTML <link rel=alternate>, fall back to /feed, /rss, /atom.xml, /index.xml, common paths, and try the URL itself as a feed.
- `add_feed(args:{url:string,folderId?:number|null,title?:string|null}) -> Feed` — inserts a pending subscription by normalized URL and returns before network access. A worker discovers/fetches/parses it; a separate media worker caches images. Failed fetches retain an editable subscription with error status.
- `add_feeds(args:{url:string,folderId?:number|null,title?:string|null}[]) -> {feeds:Feed[],failures:string[]}` — saves and queues a batch, reporting individual validation failures while preserving successful additions.
- `update_feed(args:{id:number,url?:string,title?:string,folderId?:number|null,fetchInterval?:number,isActive?:boolean}) -> Feed` — atomic patch. A changed URL preserves feed/article identities and user state, resets validators/source metadata, and queues a new fetch. Reject duplicate/unsupported URLs and changes while the same feed is fetching. Missing folderId preserves the folder; null moves it to Uncategorized.
- `delete_feed(id:number) -> Counts` (also deletes articles, tag links, cached media rows; leave files for janitor)
- `refresh(feedId?:number|null, scheduled?:boolean=false) -> { newArticles:number, updated:number, failed:number, failures:string[] }` — conditional GET using ETag/Last-Modified, parse via feed-rs, sanitize HTML with ammonia, store content_text, reading time, cover image, FTS. Articles, FTS updates, metadata, and validators commit in one immediate transaction, with no network access inside it. Scheduled refreshes select only feeds due by their individual fetch interval; explicit/manual refresh bypasses intervals. The frontend wakes at the earlier of the next feed deadline or the global check interval; 0 disables periodic checks. Startup uses scheduled selection. Emits event `refresh:progress` {done,total,feedId,title}, then `refresh:done` {newArticles,updated,failed,failures:string[]} so errors reach the UI even when the event precedes the command response. Retention cleanup runs after refresh for positive retentionDays, preserving unread/starred articles. Optional system notifications announce new articles. Frontend listens via `@tauri-apps/api/event`.
- `refresh_status() -> { running:boolean, lastRun:string|null }`
- `feed:updated` event `{feedId:number,loading:boolean,error?:string|null}` — emitted as subscriptions start/finish and after media caching; reload bootstrap and the article list as appropriate. Poll while pending/fetching subscriptions remain as a fallback for missed events. First fetches resume after restart; manual refresh skips pending/fetching feeds. Failed subscriptions emit their error for a toast; saved feed errors remain visible in Manage feeds.
- `create_folder(name:string) -> Folder`; `rename_folder(id:number,name:string) -> void`; `delete_folder(id:number) -> void` (feeds moved to uncategorized)
- `create_tag(name:string,color:string) -> Tag`; `rename_tag(id:number,name:string,color?:string) -> void`; `delete_tag(id:number) -> void`
- `create_tags(names:string[],color:string) -> Tag[]` — create a batch in one transaction; trim names, skip empty entries, and reuse existing/repeated names with case-insensitive matching. Preserve existing tag colors/counts and return each tag once. Both tag creation forms split comma-separated input before invoking this command; the reader assigns the returned tags to its current article.
- `set_article_tags(articleId:number, tagIds:number[]) -> Tag[]`
- `list_tags() -> Tag[]`
- `start_tts(sessionId:string) -> void` — starts a native speech session with its own cancellable RunOptions; cancels a previous session. Does not download or load the model.
- `synthesize_tts(sessionId:string,voice:string,tokens:number[]) -> ArrayBuffer` — validates the enabled setting, English voice, padded phoneme IDs (3–160; a bounded memory budget below the 512-token model context), and canonical cache paths. A blocking worker lazily opens one native CPU ONNX session and emits little-endian float32 mono PCM at 24 kHz via binary IPC. One intra/inter-op thread, sequential execution, no idle spinning/arena/memory-pattern cache. Reuses the session only during playback; ignores stopped sessions and validates finite audio output.
- `stop_tts(sessionId:string) -> void` — cancels matching RunOptions immediately and releases the native session after in-flight inference exits; stale stop requests cannot cancel a newer playback.
- `prepare_tts(voice:string) -> void` — requires saved `ttsEnabled`; a blocking worker serializes downloads of pinned Kokoro q8 model/tokenizers and the selected official English voice. Valid cached files are reused, size/SHA-256 verified, partial downloads discarded on failure, disabling interrupts downloads at progress checks. Emits `tts:download {file,received,total}`. Assets are stored in `tts/<revision>/` beside SQLite and excluded from backup ZIPs; existing cache survives restore. `tyler-tts://localhost/<asset>` (or `/<model-id>/<asset>`) serves only allowlisted existing cache entries while enabled, with canonical containment and no network access.
- `get_settings() -> Settings`; `set_settings(patch:Partial<Settings>) -> Settings`
- `opml_import(path:string) -> { imported:number, skipped:number, failures:string[] }` — accepts OPML path; creates folders; fetches feeds sequentially; returns fast enough (<30s typical).
- `opml_import_url(url:string) -> { imported:number, skipped:number, failures:string[] }` — fetches an OPML document over HTTP(S) and imports it with the same rules.
- `opml_export(path:string) -> { count:number }`
- `export_backup(path:string) -> { path:string, bytes:number }` — ZIP of DB (consistent SQLite backup via VACUUM INTO temp) + media/. Exclude nothing else. `.tyler.zip`.
- `import_backup(path:string) -> Bootstrap` — safely extract, validate SQLite integrity/foreign keys/schema/library queries, and migrate in staging. Refuse replacement while library connections/media operations are active. Move current DB/WAL/SHM/media to `<dir>.backup-<timestamp>-<uuid>`, install the staged library, and roll back installation errors. Prune older safety copies only after success and return fresh bootstrap.
- `data_info() -> { dataDir:string, dbPath:string, dbBytes:number, mediaBytes:number, mediaFiles:number, articles:number, feeds:number }`
- `cleanup_articles(args:{olderThanDays:number, keepStarred:boolean, keepUnread:boolean}) -> { removed:number }`
- `get_stats() -> { totalArticles:number, unread:number, starred:number, read:number, feeds:number, folders:number, tags:number, perFeed:{feed_id,title,count,unread}[], perDay:{date:string,count:number}[], oldest:string|null }`
- `cache_article_media(articleId:number) -> { cached:number, failed:number }` — download up to 25 inline images to media/articles/<id>/<sha>.<ext>, insert into media table, return; stored HTML retains remote URLs and content_html rewrite happens on next get_article for cached files that exist. Also used for reader "Save images".
- `save_image_from_url(url:string) -> string` (returns `tyler-media://localhost/<relpath>`) used for feed icons in onboarding? Not required.
- `open_data_dir() -> void` — ensure the data directory exists, resolve its actual path, and open it through the backend opener plugin using the system file manager. Takes no frontend path; honors `TYLER_DATA_DIR` and returns opening errors to Settings.
- `ping() -> string` health check.

Download limits: `feedDownloadLimitMb` defaults to 20, accepts whole numbers from 1–100, and is exposed as `feed_download_limit_mb` in the UI. Feed fetches, discovery (including fallback probes), and OPML links enforce the limit after decompression, including responses without Content-Length. Oversized downloads identify the host and limit and direct users to Settings → Feeds & storage → Feed download limit before retrying. Discovery and OPML dialogs display the error; feed failures persist on the subscription and appear in refresh/subscription notifications. Full-article source and image downloads keep their separate 5 MiB caps.

Article content rewrite: sanitized HTML: allow common tags, strip scripts/styles/forms/objects; iframe sources are limited to HTTPS YouTube /embed/ and Vimeo /video/ players, force links target=_blank, add rel=noopener noreferrer, resolve relative URLs against article URL, rewrite cached images to `tyler-media://localhost/<relative path>`. Image src must not break CSP.

Summary compatibility: if a request with `max_tokens` is rejected with HTTP 400/422 and the error message names both `max_tokens` and `max_completion_tokens`, retry once with the latter field and the same budget. Do not retry successful requests or unrelated provider errors. A model may consume a small output budget on reasoning alone; empty visible content is an error and never cached.

Media paths are relative to the data directory, including `media/`. Schema version 3 repairs older paths/URLs. Version 4 adds the full-content flag/enclosures, clears HTTP validators once for reparsing, and is accepted by backup restore. All serving and deletion must use canonical containment checks inside the media directory; database paths are untrusted. The frontend preserves the generated local image URLs during sanitization and converts custom-protocol URLs through Tauri for the current platform.

## Local text to speech

Settings → Read aloud explicitly enables the ~92 MB Kokoro ONNX q8 download, selects among 28 official American/British English voices (about 0.5 MB each), shows progress/error/retry, and persists `ttsKeepPlaying`. Default is disabled, Heart voice, and stopping on article changes. Model ID: `onnx-community/Kokoro-82M-v1.0-ONNX`; revision and SHA-256 manifest are pinned in the backend. The 82M label is a parameter count. Article text stays local.

Global title-bar play/pause/stop controls beside the command palette operate on the source article across navigation. Playback snapshots title/current body (summary fallback), respects navigation preference, and stops on disable/import/unmount. Voice changes apply next time. An English-only phonemization worker produces Kokoro IPA/token IDs using its cached vocabulary, with no model/GPU/WASM inference in the webview. Sentence/word segments are bounded to 160 characters (80 for the first phrase) and subdivided against a 160-token phoneme budget without truncation, bounding activation memory below the model's 512-token context. Native single-threaded CPU inference runs in Rust, with idle spinning and allocator arenas disabled. The first finished segment plays immediately while exactly one upcoming segment is prepared; Web Audio schedules continuous PCM. Pause stops lookahead after an already-running segment; stop terminates the worker, closes audio, cancels native inference, and releases the model. `ort` statically bundles the CPU runtime with the app; no Python or runtime download is required for users.

## Frontend conventions
- Settings → Reading → Load full article by default (`load_full_article_by_default` / `loadFullArticleByDefault`) defaults to false. Enabling it loads the current article; subsequent opens fetch/extract/save full text unless already saved. Manual loading uses the same in-flight request guard. Automatic successes stay silent; failures retain readable feed content and allow manual retry.
- Reader's regular and compact action bars include one-click Summarize using the saved prompt. App owns per-article/configuration summary jobs so generation continues during navigation without opening a modal, stealing focus, or disabling reader shortcuts. While pending, the existing sparkle icon pulses (honoring reduced motion) and the button reads Summarizing…, with no summary loading bar; completed results appear in a dismissible reader panel with independent scrolling and a Copy button. Reopening reuses memory, and content/settings changes select a different result. Imports clear frontend jobs and ignore old completions. Settings → LLM summaries is a form with an explicit Save LLM settings button; other settings retain immediate saving. The API key is a password field, stored as a local setting and included in backups. Render generated text as plain text.
- Import API: `import { api } from "./api";` where `api` wraps `invoke` and maps commands; all return promises. `api.bootstrap()`, `api.listArticles(query)`, `api.getArticle(id)`, `api.setArticleState(id, patch)`, `api.markAllRead(scope)`, `api.addFeed({url,folderId,title})`, `api.discoverFeeds(url)`, etc. Paths use camelCase args.
- Toasts: Foundation exports `useToast()` from `./store` returning `{ push(message, kind?) }`; kind = "info"|"success"|"error".
- Theme: set `document.documentElement.dataset.theme = "light"|"dark"`; "system" follows `matchMedia("(prefers-color-scheme: dark)")`; persist via settings. All colors via CSS vars.
- All icons: `lucide-react`. No emoji-only icons. No external images/logos except feed icons.
- Keyboard: Cmd/Ctrl+K palette, `/` search, Down/Up arrows next/prev article (prevent native scrolling when handled), m toggle read, s star, u mark unread, r refresh, Esc close palette/reader. Don't hijack article navigation while typing in input/textarea/select/contenteditable or using overlays. Command-palette selection uses Ctrl+N/Ctrl+P for next/previous result on all platforms; consume these events inside the palette. Enter opens the selected result. Update the shortcut sheet, reader hints, and website when changing bindings.
- Cmd/Ctrl with `+`/`=` increases reader font size and `-` decreases it in 1 px steps (14–24 px), using the saved font-size setting. Prevent the default zoom action when handled, honor typing/overlay guards, and serialize repeated adjustments so fast presses are not lost.
- Window: custom title bar inset for macOS traffic lights (top 44px drag region). Respect safe area; no native decorations.
- Empty/loading/error states are part of the design, never blank.
- The HTML entry includes the themed loading animation before React loads; show the native window after the page finishes loading. Keep the animation visible while bootstrap opens the library.
- Sidebar folders expose rename/delete buttons; Manage feeds uses the same folder dialog. Empty folders delete immediately. Confirm non-empty folder deletion once in a styled app dialog, explaining that feeds move to Uncategorized and saved articles are kept.
- Sidebar tags expose pencil/trash buttons. The edit dialog changes name and color; unused tags delete immediately. Confirm deletion of a used tag once in a styled app dialog, explaining that saved articles are kept. Refresh the current reader after tag edits/deletion.

## Quality bar
- `npm run build` must pass; `cargo check` must pass (backend agent verifies).
- No TypeScript (plain JSX). No TODO placeholders in UI copy.
- Backend must not panic on malformed feeds, bad URLs, missing files, empty DB, network timeouts. Timeouts: feed fetch 20s, image 12s.
- SQLite: WAL, foreign_keys ON, busy_timeout 5s; FTS5 external content with triggers or explicit sync; escape FTS query tokens to avoid syntax errors.
- All mutating UI actions update counts and list without full reload where feasible.
- Background refresh merges the fresh first page into the loaded article list instead of resetting it. Keep the current cursor, loaded pages, selected row, and open reader article; new stories go at the top for newest-first and at the end for other orders. A late detail request must never replace a loaded article with an empty value.
- All SQLite/filesystem IPC handlers run inside `spawn_blocking`; network work never runs on the UI thread. First-fetch and image queues are separate, and image downloads never hold an article-ingestion write transaction.

Desktop lifecycle: native tray menu Open Tyler / Refresh feeds / Quit Tyler; closing the main window hides it. Single-instance and deep-link plugins deliver `.opml` paths and `feed:` links into a startup-safe queue. Installed bundles register OPML association and feed scheme. Native file drag/drop is enabled; sidebar feed movement uses pointer dragging.

Media: persist audio/video feed links and Media RSS URLs in article_enclosures; serve them with native controls and preload=none. Backend sanitization, frontend sanitization, and CSP permit only HTTPS www.youtube.com/embed/, www.youtube-nocookie.com/embed/, and player.vimeo.com/video/ iframes; sandbox frames and strip objects/scripts/forms. Find in article highlights up to 1,000 literal case-insensitive body matches with next/previous navigation. Full content and enclosure metadata are included in portable backups; streaming media is not downloaded.
